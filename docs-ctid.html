实人认证 API

POST /v1/realname：提交姓名、身份证号和人像图片，判断是否为同一人。JSON 请求，X-API-Key 鉴权。

实人认证会核验人像，属于敏感个人信息场景。客户须取得用户单独同意，并在隐私政策中说明第三方核验。详见 合规说明。

示例数据为脱敏占位，实际请传真实业务数据（我方不存储）。

2. 返回

成功（一致）：

{
  "code": "OK",
  "request_id": "r_2f8a1c...",
  "result": { "match": true, "level": "realname" },
  "billed": true
}

核验完成但不一致：

{
  "code": "NO_MATCH",
  "request_id": "r_2f8a1c...",
  "result": { "match": false, "level": "realname" },
  "billed": true
}

失败（参数错误示例）：

{
  "code": "PARAM_INVALID",
  "message": "图片大小需在 5–50KB 之间",
  "request_id": "r_2f8a1c...",
  "billed": false
}

3. 返回码

全部端点共用一套我方返回码，计费口径一致：

codeHTTP计费含义
OK200是核验完成且一致
NO_MATCH200是核验完成但不一致
PARAM_INVALID400否参数格式错误
KEY_INVALID401否Key 无效或停用
NOT_AUTHORIZED403否无该产品权限
QUOTA_EXCEEDED402否余额不足
RATE_LIMITED429否超 QPS 或日上限
UPSTREAM_TIMEOUT504否上游超时
UPSTREAM_ERROR502否上游异常
INTERNAL500否我方内部错误

完整说明见 API 文档 · 返回码。

4. 限流、额度与幂等

  • QPS：每个 Key 默认 5 次/秒，超限返回 RATE_LIMITED；提额联系对接人。
  • 日上限：默认 10,000 次/天。
  • 额度：按调用扣减，余额不足返回 QUOTA_EXCEEDED。
  • 幂等：带 Idempotency-Key，同 Key 60 秒内重复请求返回首次结果，不重复计费。

5. 数据怎么处理

  • 照片只在内存中转发，处理完即丢弃，不落盘、不写日志；
  • 姓名、身份证号不落库、不写日志；
  • 日志只保留 request_id、Key 前缀、端点、我方码、是否计费、耗时；
  • 错误信息不回显用户输入内容。

6. 常见问题

图片有什么要求？

JPG 格式，Base64 后提交，原图大小 5–50KB。太小或太大都会返回 PARAM_INVALID。

返回 NO_MATCH 是什么意思？

姓名、身份证号、人像三者未能匹配。业务上建议拒绝或转人工，不要直接封号。

失败会计费吗？

不计费。OK 和 NO_MATCH 计费，其余返回码都不计费。

支持视频活体吗？

当前接口接收静态图片，不支持视频流。
