快速开始

拿 Key → 发第一笔请求 → 看返回码。一条 curl 就能跑通，不需要签名。

前置条件：已拿到 X-API-Key（申请试用后发放），以及 API 地址。示例里的域名是占位，用开通时给的。

1. 设置 Key（1 分钟）

export API_KEY="ak_live_你的Key"
export API_BASE="https://【开通时给的域名】"

Key 只放服务端，不要写进前端、App 包或代码仓库。

2. 发第一笔二要素（2 分钟）

curl -s -X POST "$API_BASE/v1/id2" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"张*","id_number":"110101********1234"}'

成功返回：

{
  "code": "OK",
  "request_id": "r_2f8a1c...",
  "result": { "match": true, "level": "id2" },
  "billed": true
}

3. 三要素 / 实人认证（3 分钟）

三要素多一个手机号：

curl -s -X POST "$API_BASE/v1/id3" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"张*","id_number":"110101********1234","mobile":"138****5678"}'

实人认证多一个 image_base64（JPG，5–50KB）：

B64=$(base64 -i face.jpg | tr -d '\n')
curl -s -X POST "$API_BASE/v1/realname" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"张*\",\"id_number\":\"110101********1234\",\"image_base64\":\"$B64\"}"

4. 看返回码（2 分钟）

code含义怎么办
OK一致放行
NO_MATCH不一致拒绝或转人工
PARAM_INVALID参数错核对字段格式，不重试
KEY_INVALIDKey 无效检查 Key
RATE_LIMITED超 QPS退避重试
UPSTREAM_TIMEOUT / UPSTREAM_ERROR上游异常带 Idempotency-Key 重试

完整码表见 API 文档 · 返回码。

跑不通？先查四条

  1. Key 没生效：echo $API_KEY 确认；请求头是 X-API-Key，不是 Authorization。
  2. 路径不对：/v1/id2、/v1/id3、/v1/realname，大小写敏感。
  3. 字段名不对：id_number 不是 idcard；三要素是 mobile。
  4. 图片太大/太小：JPG 原图 5–50KB，Base64 后提交。

跑通之后

  • 日志记 request_id，报障只提供它，不发请求内容；
  • 重试用 Idempotency-Key，避免重复计费；
  • QPS 超了退避，不要并发硬打；
  • 余额低于 20% 配告警。
