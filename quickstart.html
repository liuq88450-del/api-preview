30 分钟快速开始

下载示例 → 填 Key → 发请求 → 看返回码。四步，不用等商务。

前置条件：已拿到 AppID / AppSecret（申请试用后邮件发放），以及正式接口文档里的域名和签名规则。示例代码里的域名、字段名是占位，按文档替换。

第 0 步：下载示例（约 2 分钟）

三份任选其一，逻辑一样：

  • quickstart.py（Python 3.8+，无第三方依赖）
  • quickstart.js（Node 18+，用内置 fetch）
  • quickstart.sh（curl + openssl）

说明见 samples/README.md。

第 1 步：填 Key（约 5 分钟）

用环境变量，不要写死在代码里：

export RN_BASE_URL="https://【按正式文档填】"
export RN_APP_ID="app_xxxxx"
export RN_APP_SECRET="【开通时下发的密钥】"

Windows PowerShell：

$env:RN_BASE_URL="https://【按正式文档填】"
$env:RN_APP_ID="app_xxxxx"
$env:RN_APP_SECRET="【开通时下发的密钥】"

第 2 步：发请求（约 10 分钟）

二要素（姓名 + 身份证）：

python3 quickstart.py two "张*" "110101********1234"

三要素（再加手机号）：

python3 quickstart.py three "张*" "110101********1234" "138****5678"

Node：

node quickstart.js two "张*" "110101********1234"

PowerShell 里如果引号被吃掉，改用程序里的默认示例值，或把参数写进脚本。

示例里的姓名、证件号、手机号都是脱敏占位，直接发会返回参数错误。换成你自己的测试数据（虚构或已脱敏），不要用真实客户数据。

第 3 步：看返回码（约 10 分钟）

成功时返回类似：

{
  "code": "0",
  "msg": "success",
  "request_id": "req_...",
  "order_no": "quickstart-1762646400",
  "result": 1,
  "result_desc": "一致"
}

对照这张表判断下一步：

看到什么含义怎么办
result = 1一致跑通了，可以接业务
result = 2不一致正常返回，检查测试数据是否匹配
result = 3查无记录正常返回，业务上转人工
签名错误 / 时间戳过期鉴权问题核对密钥、拼接顺序、服务器时间
参数缺失 / 格式错请求问题核对字段名、长度、全角字符
余额不足 / 无权限额度问题看控制台余额，免费额度用完就买包
限流 / 超时流量问题降并发、指数退避重试

跑不通？先查这四条

  1. 密钥环境变量没生效：另开终端、重设一次，或 `echo $RN_APP_ID` 确认。
  2. 签名规则抄错：待签串顺序、空值是否参与、是否 URL 编码，以正式文档为准。
  3. 时间戳偏差：服务器时间不准，误差超过窗口会被拒。
  4. 字段名不一致：二要素是 name + idcard，三要素多一个 mobile；别把 mobile 传给二要素接口。
