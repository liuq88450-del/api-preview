API 文档

一个端点：POST /v1/id3，核验姓名、身份证号、手机号是否属于同一人。一套鉴权、一套返回码。

请求和返回都是 JSON；鉴权只用一个请求头 X-API-Key。不需要签名、不需要拼时间戳。

不想看长文？直接走快速开始 →

1. 端点

端点用途必填字段
POST /v1/id3三要素核验name, id_number, mobile

2. 鉴权

每个请求带一个 Key：

X-API-Key: ak_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Key 在控制台创建，只存哈希；泄露后在控制台重置，旧 Key 立即失效。Key 不要写进前端、App 包或代码仓库，用环境变量注入。

3. 请求

3.1 三要素

字段类型必填说明
namestring是姓名，1–40 字符
id_numberstring是18 位身份证号，末位可为 X
mobilestring是11 位手机号
curl -s -X POST https://api.example.com/v1/id3 \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"张*","id_number":"110101********1234","mobile":"138****5678"}'

示例里的姓名、证件号、手机号是打码的，直接复制会返回 PARAM_INVALID；换成你自己的测试数据即可跑通。

4. 返回

成功（一致）：

{
  "code": "OK",
  "request_id": "r_2f8a1c...",
  "result": { "match": true, "level": "id3" },
  "billed": true
}

核验完成但不一致：

{
  "code": "NO_MATCH",
  "request_id": "r_2f8a1c...",
  "result": { "match": false, "level": "id3" },
  "billed": true
}

失败：

{
  "code": "PARAM_INVALID",
  "message": "身份证号格式错误",
  "request_id": "r_2f8a1c...",
  "billed": false
}
字段说明
code我方返回码，见第 5 节
message失败时的提示，不含用户输入内容
reason机器可读原因码（如 ID_FORMAT_INVALID、IDENTITY_NOT_MATCHED），用于自查
request_id请求唯一号，排障与对账用，请落日志
result.match是否一致；失败时没有该字段
result.level固定为 id3
billed本次是否计费

5. 返回码

每个码都可以直接跳转，例如 /docs#NO_MATCH。

codeHTTP计费含义建议处理
OK200是核验完成且一致放行
NO_MATCH200是核验完成但不一致拒绝或转人工
PARAM_INVALID400否参数格式错误修正参数，不要重试
KEY_INVALID401否Key 无效或停用检查 Key，不要重试
NOT_AUTHORIZED403否无该产品权限联系我方开通
QUOTA_EXCEEDED402否余额不足充值
RATE_LIMITED429否超 QPS 或日上限退避重试
UPSTREAM_TIMEOUT504否上游超时幂等重试 1–2 次
UPSTREAM_ERROR502否上游异常幂等重试 1–2 次
INTERNAL500否我方内部错误重试一次，仍失败联系我方
NOT_FOUND404否端点不存在检查路径

只有 OK 和 NO_MATCH 计费，其它一律不计费。

6. 服务说明

核验数据来自多个合法数据源，不同数据源的覆盖范围不同，同一人在不同时间、不同通道的结果可能不一致。

  • 我们不承诺 100% 准确率，也不承诺通过率；
  • 只承诺服务可用性（以 SLA 为准）与报错不计费；
  • 失败时返回 code / reason，帮助客户自查；
  • 常见不通过原因见 核验不通过的常见原因。

7. 错误处理

  • 4xx 不要重试：参数、Key、权限、余额问题，重试结果一样。
  • 429：指数退避（1s / 2s / 4s），最多 3 次。
  • 502 / 504 / 500：带同一个 Idempotency-Key 重试，避免重复计费。
  • 所有失败响应都带 request_id，报障时提供它即可，不用发请求内容。

8. 限流、额度与幂等

项默认说明
QPS5 次/秒单 Key；超限返回 RATE_LIMITED，可申请提额
日上限10,000 次/天单 Key；超限返回 RATE_LIMITED
额度按资源包余额不足返回 QUOTA_EXCEEDED
幂等60 秒同 Key + Idempotency-Key 返回首次结果，不重复计费

提额联系对接人，说明峰值 QPS、时段、持续时长，一般 3 个工作日生效。

9. 数据处理

  • 请求体（姓名、身份证号、手机号、照片）不落库、不写日志；
  • 日志只保留 request_id、Key 前缀、端点、我方码、是否计费、耗时；
  • 照片只在内存中转发，处理完即丢弃；
  • 错误信息不含用户输入内容；
  • 客户须在隐私政策中告知用户并取得同意，详见 合规说明。

10. 常见问题

为什么不需要签名？

鉴权只校验 X-API-Key。Key 放在服务端，不要暴露给前端。

返回 NO_MATCH 会收费吗？

会。核验已完成（拿到了"不一致"的结论），按次计费。

超时了能重试吗？

能，但要带同一个 Idempotency-Key，避免同一笔请求被计费两次。

一个 Key 能调哪些端点？

只开放三要素 /v1/id3；其它端点不在服务范围。

为什么核验不通过？

常见原因是信息填写、数据源延迟、特殊证件类型、通道覆盖差异。见 核验不通过的常见原因。
