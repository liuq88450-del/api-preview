接入文档

两个产品：二要素核姓名 + 身份证号，三要素再加手机号。两套接口的鉴权、错误处理、限流规则一致，只有请求字段不同。

关于参数细节：接口域名、签名算法、字段名与业务码值以开通时下发的正式接口文档为准。本文给出接入结构与排障方法，示例中的姓名、证件号、手机号均为脱敏虚构数据。

1. 两个产品与边界

产品核验字段适合场景返回
二要素姓名 + 身份证号注册、入驻、活动防刷一致 / 不一致 / 查无记录
三要素姓名 + 身份证号 + 手机号下单、提现、开卡一致 / 不一致 / 查无记录

本接口不提供

  • 身份证归属地、生日等衍生信息，或"是否为本人持证"的担保；
  • 三要素以外的核验能力（如证件照片识别），这类需求由客户自有产品解决；
  • 100% 覆盖承诺——号码状态变化、库更新延迟都可能导致"查无记录"。

核验结果仅用于客户自身业务的身份一致性判断，不具备司法鉴定效力，不能替代公安机关出具的证明文件，不得转售或二次分发。

2. 接入流程

  1. 领免费额度注册后自动发放：二要素 100 条、三要素 50 条，7 天有效。
  2. 下载示例Python / Node / curl 三份，按快速开始跑通。
  3. 试跑用脱敏数据核验一笔，确认返回结构与码值。
  4. 买资源包按用量选包，在线支付或对公转账，款到开额度。
  5. 上线换生产 Key，配置超时、退避、余额告警。

3. 鉴权与密钥

两套接口共用同一套鉴权：AppID + AppSecret 签名。每个请求携带应用标识、时间戳、随机串与签名，服务端用密钥复算签名后校验。签名算法、待签字符串规则、时间戳窗口以正式文档为准。

密钥安全

  • AppSecret 只放服务端，不得写进前端、App 包或代码仓库；
  • 用环境变量或配置中心注入；
  • 测试与生产密钥分开，上线前更换；
  • 发现泄露立即轮换。

防重放

  • 每次请求生成新的随机串（nonce）；
  • 时间戳偏差不要超过允许窗口；
  • 同一业务单号幂等，重试不重复计费。

签名逻辑示意（仅演示结构，真实规则以正式文档为准）：

# Python 示意：参数排序拼接后做摘要
import hashlib, hmac, time, uuid

def build_sign(params: dict, secret: str) -> str:
    items = sorted((k, str(v)) for k, v in params.items()
                   if k != "sign" and v != "")
    raw = "&".join(f"{k}={v}" for k, v in items)
    return hmac.new(secret.encode(), raw.encode(),
                    hashlib.sha256).hexdigest()

params = {
    "app_id":    "app_xxxxx",
    "timestamp": str(int(time.time())),
    "nonce":     uuid.uuid4().hex[:16],
    "order_no":  "c_20261109_0001",
    "name":      "张*",                  # 示例为脱敏数据
    "idcard":    "110101********1234",
}
params["sign"] = build_sign(params, "YOUR_APP_SECRET")

6. 错误处理

错误分六类，处理策略不同：

类别典型表现是否计费处理
参数类缺字段、格式错、编码问题否修正后重试，不要盲目重试
鉴权类签名错、时间戳过期、密钥停用否核对密钥与拼接规则，不重试
权限与余额无权限、余额不足、应用停用否联系我方，不重试
限流超出并发或日调用上限视规则指数退避后重试
上游异常超时、系统错误视规则幂等重试 1–2 次，仍失败转人工
核验结果类不一致、查无记录是按业务规则处理，不重试

排查顺序

  1. 取 request_id 和错误码，先判断请求是否到达我方；
  2. 参数类：核对字段名、必填、长度（证件 18 位、手机 11 位）、有无全角字符；
  3. 鉴权类：核对待签串顺序、是否漏了空值参数、密钥是否用错环境；
  4. 超时类：先查幂等结果，确认没成功再重试；
  5. 结果异常（该一致却不一致）：确认用户输入有无空格、曾用名、生僻字。

重试只对超时、5xx、限流做，指数退避 1s / 2s / 4s，最多 3 次，必须带同一个 order_no。

7. 并发与限流

并发与限流能力由上游（腾讯云）保障，我方负责按你的业务量申请额度并协助压测。每个应用有默认并发与日调用上限，开通时确认。

怎么申请提额

  1. 提前 3 个工作日联系对接人，说明峰值 QPS、时段、持续时长；
  2. 我方提交上游评估，按结果调整该应用的并发与日上限；
  3. 生效后按新额度压测（80% 目标压 10 分钟），确认超时率正常再放量；
  4. 临时活动可申请短期提额，结束后自动回落。

客户端建议：本地令牌桶按签约上限的 80% 跑；批量场景串行化；错误率超 20% 熔断 30 秒。

8. 数据处理

  • 只传必需字段：二要素传姓名、证件号；三要素多传手机号。不附加地址、单位、照片；
  • 不留存明文：我方通道不做业务留存，只保留不含明文身份信息的调用日志；
  • 日志脱敏：客户侧证件号中间 8 位、手机号中间 4 位打码；
  • 全链路 HTTPS，不通过明文 HTTP、短信或聊天工具传身份信息；
  • 不得二次利用：结果只用于身份核验，不做画像、营销或对外提供。

客户须在自身隐私政策中告知用户并取得同意。详见 合规说明。

9. 常见问题

二要素和三要素能同时用吗？

能。两个产品独立计费、独立余额，同一账号可以分别购买。

为什么有的身份证返回"查无记录"？

可能是号码新办未入库、异地数据延迟，或用户输入有误。这类结果不应直接判拒，建议转人工。

支持批量吗？

以正式文档为准。若无批量接口，客户端串行调用并控制并发。

结果可以缓存吗？

缓存时长以合同约定为准。建议只缓存结论与时间，不缓存明文；号码或姓名变更后必须重新核验。

密钥泄露了怎么办？

立即联系对接人轮换，并检查异常调用。轮换期间新旧密钥可并行一小段时间。
